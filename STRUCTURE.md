# Структура проекта DemoApi

**DemoApi — backend-сервис с REST API.** У него нет своего интерфейса: он принимает HTTP-запросы и отвечает JSON. Обращаться к нему может кто угодно, кто умеет отправлять HTTP: браузер (страница Swagger), Postman, файл `DemoApi.http` в Visual Studio, `curl`, сайт или мобильное приложение.

```
клиент (Swagger, Postman, сайт) ──HTTP + JSON──▶ DemoApi ──SQL──▶ PostgreSQL
```

## Что где лежит

Так проект выглядит в *Обозревателе решений* Visual Studio:

```
src/DemoApi
├── Connected Services         мастер VS для облачных сервисов — не используем
├── Properties/
│   └── launchSettings.json    как запускать из VS: адрес, что открыть в браузере, переменные окружения
├── Зависимости                .NET и NuGet-пакеты
├── Controllers/               приём HTTP-запросов и ответы клиенту
├── Services/                  действия с данными + запись в лог
├── Domain/                    что такое «проект» и «задача», правила статусов
├── Data/                      хранение: SQL для PostgreSQL
│   └── InMemory/              хранение в памяти процесса (без БД)
├── appsettings.json           настройки
├── DemoApi.http               готовые запросы к API
└── Program.cs                 точка входа: из чего собран сервис
tests/DemoApi.Tests
├── Unit/                      проверка правил без HTTP и БД
└── Integration/               проверка всего сервиса через HTTP
```

| Узел | Зачем | Когда туда идти |
|---|---|---|
| **Connected Services** | Мастер Visual Studio для подключения облачных сервисов. Появляется в любом веб-проекте сам | Не используем |
| **Properties/launchSettings.json** | Запуск из Visual Studio: адрес `http://localhost:8080`, открыть `/swagger`, переменные окружения (`ASPNETCORE_ENVIRONMENT=Development`). В Docker-образ не попадает | Сменить порт, задать переменную окружения для локального запуска |
| **Зависимости** | Подключённые пакеты: Swagger, драйвер PostgreSQL, health checks, метрики Prometheus | Добавить пакет: ПКМ → *Управление пакетами NuGet* |
| **Controllers** | Адреса API (`api/projects`, `api/tasks`), разбор запроса, код ответа: 200, 201, 404, 409. Внизу файла — записи `...Request`: какие поля клиент присылает и как их проверять (`[Required]`, `[StringLength]`) | Новый адрес API, новый код ответа, новое поле в запросе |
| **Services** | Действия: создать, переименовать, удалить, сменить статус. Пишут в лог, что сделали | Новое действие с данными |
| **Domain** | Записи `Project`, `TaskItem`, `ProjectStats` — их же сервис отдаёт клиенту в JSON. `StatusRules` — какие переходы статуса разрешены | Новое поле, новое правило |
| **Data** | Интерфейс `IProjectRepository` — что умеет хранилище. `ProjectRepository` — как это сделано на SQL. `DatabaseInitializer` создаёт таблицы при старте | Новый запрос к БД |
| **Data/InMemory** | То же хранилище, но в памяти: сервис запускается без БД. Данные пропадают при остановке | То же, что в `Data`, — оба варианта должны уметь одно и то же |
| **appsettings.json** | Настройки: `Storage` (`InMemory` или `Postgres`), уровни логов. `appsettings.Development.json` (раскройте стрелку) перекрывает их при запуске из VS: строка подключения к БД | Сменить хранилище, строку подключения |
| **DemoApi.http** | Запросы к API прямо из Visual Studio: *Send Request* над каждым | Проверить API без браузера |
| **Program.cs** | Сборка сервиса: какое хранилище, Swagger, health checks, метрики, логи | Подключить пакет или новую возможность |
| **tests** | `Unit/` — правила за миллисекунды. `Integration/` — сервис целиком: отправляют HTTP-запросы и проверяют ответы | После любого изменения: *Test Explorer → Run All* |

## Как проходит запрос

`PATCH /api/tasks/5/status` с телом `{ "status": "Done" }`:

```
TasksController.ChangeStatus
  ├─ TaskService.GetAsync(5) ──▶ хранилище ──▶ задачи нет?          ──▶ 404
  ├─ StatusRules.CanTransition(Todo, Done)  ──▶ переход запрещён?   ──▶ 409
  └─ TaskService.ChangeStatusAsync          ──▶ хранилище + лог     ──▶ 200 + задача в JSON
```

Все проверки видны в одном методе контроллера. Если код упал с исключением, ASP.NET вернёт **500** и запишет ошибку в лог.

## Почему так

- **Каждая папка — одна забота.** Меняется формат запроса — правим контроллер. Меняется правило — `Domain`. Меняется база — `Data`.
- **Хранилище подменяется настройкой.** `Services` знают только интерфейс `IProjectRepository`. `InMemory` или PostgreSQL — решает `Program.cs` по настройке `Storage`. Поэтому в теме 3 мы подключаем БД, не трогая контроллеры и сервисы.
- **Правила проверяются без запуска сервиса.** `StatusRules` — обычный C#-класс, тест проверяет его за миллисекунды.

Меньше нельзя: если всё сложить в `Program.cs`, через 15 адресов файл станет нечитаемым. Больше не нужно: в больших системах слои выносят в отдельные проекты, но для одного сервиса это лишняя сложность.
